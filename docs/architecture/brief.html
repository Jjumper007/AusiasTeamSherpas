Caso → brief #2

Convierte los archivos de un caso y la encuesta de una persona en todo lo que necesita el pipeline: el brief para Claude, los facts con las cifras permitidas y las opciones de la encuesta. Determinista, sin LLM.

El módulo

Interfaz que necesita el pipeline
  • loadCase(caseId) → CaseData
  • generateCaseOutputs(caseData, memberFirstName, survey) → { brief, facts, factsSource, surveyOptions }
  • listCaseIds() → string[]
  • surveyOptionsForCase(caseId) → SurveyOption[]
  • BriefError: entrada inválida, con un mensaje listo para mostrar
Implementación que esconde (23 archivos, ~1.350 líneas)
case-loadercase-schema (zod del JSON)persona-parser brief-extractornarrative-selectordecision-style pillar-pointstopic-coveragesurvey-options facts/score-factsfacts/household-factsfacts/plan-facts facts/curated-factsfacts/goal-factsfacts-source
Quien llama no sabe nada de los formatos de persona.md (que varían entre casos), de cómo se eligen los textos de la narrativa ni de dónde sale cada cifra. Esa es la profundidad del módulo.

Qué pasa dentro

El seam: CaseData

El módulo tiene dos versiones de cada función: una que recibe el id del caso y lee el disco (extractBrief, generateFacts, surveyOptionsForCase) y otra pura que recibe CaseData (buildBrief, buildFacts, buildSurveyOptions). El seam real está en CaseData: el pipeline carga el caso una vez y genera todo a partir de él.

Errores

Todo problema de entrada lanza BriefError con un mensaje de una línea: caso desconocido, miembro desconocido, miembro que es un hijo (los hijos aparecen en household pero no tienen vídeo), encuesta inválida o archivo del caso ilegible. El pipeline puede enviar ese mensaje tal cual por SSE.

Observación de diseño

La interfaz publicada es más ancha que la necesaria. backend/src/brief/index.ts exporta 15 nombres, incluidos detalles internos (parsePersona, overrideD5, coveredTopics). La CLI, además, importa archivos internos directamente.

Propuesta: que index.ts exporte solo las cinco piezas de arriba y que la CLI pase por él. Las piezas internas siguen teniendo sus tests; simplemente dejan de ser parte de la interfaz.

Código: backend/src/brief/. Tests: 82, en 5 archivos (npx vitest run backend/src/brief).
